The security header everyone pastes and nobody can read. Read it.

CspWhy evaluates a Content-Security-Policy the way a browser does: which directive actually governs each resource through the fallback chain, which source expression matches which URL, and the three traps that silently neuter most policies.

The traps, named

script-src 'none' 'self' looks like a typo-net and blocks everything - 'none' wins. img-src *.example.com refuses example.com itself. And an inline onclick= stays blocked even when script-src-elem allows your CDN, because attributes walk a different chain.

Every verdict shows its chain

A worker script falls back worker-src → child-src → script-src → default-src. CspWhy shows the chain it walked, the directive that answered, the source that matched, and the reason - allowed, blocked, or conditional on a nonce or hash.

Spec-checked, not vibes

The engine is cross-checked against an independent Python implementation of the same CSP3 rules on 623 policies and checks - 1,269 comparisons, zero disagreements - including duplicate directives, scheme upgrades, and non-default ports.
